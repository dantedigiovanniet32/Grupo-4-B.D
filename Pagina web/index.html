1: ¿Que es MySQL?

MySQL es un Sistema Gestor de Bases de Datos Relacionales (SGBD) de código abierto que utiliza el lenguaje SQL (Structured Query Language) para consultar, almacenar, organizar y administrar grandes volúmenes de información en tablas interrelacionadas. Su función principal es servir como motor central de datos para permitir que aplicaciones y sitios web puedan guardar, actualizar y recuperar información de manera estructurada, segura y eficiente.

2: Store Procedure

Un Stored Procedure (procedimiento almacenado) es un bloque de código SQL con nombre propio que se guarda en la base de datos y se puede ejecutar (invocar) las veces que haga falta, en vez de reescribir la misma consulta una y otra vez. Sirve para encapsular lógica repetitiva, mejorar el rendimiento y centralizar reglas de negocio en el servidor.

DELIMITER //
CREATE PROCEDURE obtenerUsuariosPorNombre(IN nombreBuscado VARCHAR(100))
BEGIN
    SELECT * FROM usuarios WHERE nombre LIKE CONCAT('%', nombreBuscado, '%');
END //
DELIMITER ;

-- Para ejecutarlo:
CALL obtenerUsuariosPorNombre('Fede');

3: SQL

Una subconsulta es un SELECT dentro de otra consulta. Se usa cuando el resultado de una consulta depende del resultado de otra. 
SELECT nombre, email
FROM usuarios
WHERE id IN (SELECT id_usuario FROM pedidos WHERE total > 1000);

Los JOIN combinan filas de dos o más tablas relacionadas por una clave en común.
INNER JOIN
Devuelve solo las filas que tienen coincidencia en ambas tablas. 
SELECT u.nombre, p.total
FROM usuarios u
INNER JOIN pedidos p ON u.id = p.id_usuario;
JOIN
Es sinónimo de INNER JOIN: si escribís JOIN sin aclarar el tipo, MySQL asume INNER JOIN. 
SELECT u.nombre, p.total
FROM usuarios u
JOIN pedidos p ON u.id = p.id_usuario;
LEFT JOIN
Trae todas las filas de la tabla izquierda, tengan o no coincidencia en la derecha (con NULL si no hay match). 
SELECT u.nombre, p.total
FROM usuarios u
LEFT JOIN pedidos p ON u.id = p.id_usuario;
RIGHT JOIN
Es el espejo del LEFT JOIN: trae todas las filas de la tabla derecha, tengan o no coincidencia en la izquierda. 
SELECT u.nombre, p.total
FROM usuarios u
RIGHT JOIN pedidos p ON u.id = p.id_usuario;
OUTER JOIN
Término general para los joins que incluyen filas sin coincidencia (LEFT, RIGHT o FULL). MySQL no tiene la palabra OUTER JOIN sola: se usa combinada con LEFT/RIGHT/FULL.
FULL JOIN
Combina LEFT y RIGHT JOIN: trae todas las filas de ambas tablas, tengan o no coincidencia. MySQL no lo soporta de forma nativa, se simula con UNION. 
SELECT u.nombre, p.total FROM usuarios u LEFT JOIN pedidos p ON u.id = p.id_usuario
UNION
SELECT u.nombre, p.total FROM usuarios u RIGHT JOIN pedidos p ON u.id = p.id_usuario;
CROSS JOIN
Devuelve el producto cartesiano: cada fila de una tabla combinada con cada fila de la otra (sin condición ON). 
SELECT u.nombre, c.nombre
FROM usuarios u
CROSS JOIN categorias c;

Filtra texto por patrones, usando % (cualquier cantidad de caracteres) y _ (un solo carácter). 
SELECT * FROM usuarios WHERE email LIKE '%@gmail.com';

Modifica la estructura de una tabla ya creada: agregar, modificar o eliminar columnas. 
ALTER TABLE usuarios ADD COLUMN telefono VARCHAR(20);

Filtra resultados después de agrupar con GROUP BY (a diferencia de WHERE, que filtra antes de agrupar). 
SELECT id_usuario, COUNT(*) AS cantidad
FROM pedidos
GROUP BY id_usuario
HAVING COUNT(*) > 5;

Ordena el resultado por una o más columnas, ascendente (ASC, por defecto) o descendente (DESC). 
SELECT * FROM usuarios ORDER BY nombre ASC;

Agrupa filas que comparten un valor en común, para poder aplicarles funciones de agregación (COUNT, SUM, AVG, etc.) por grupo. 
SELECT id_usuario, SUM(total) AS gastado
FROM pedidos
GROUP BY id_usuario;

PK (Primary Key / clave primaria): identifica de forma única cada fila de una tabla, no se repite ni puede ser NULL.
FK (Foreign Key / clave foránea): columna que referencia a la PK de otra tabla, para relacionar ambas. 
CREATE TABLE pedidos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_usuario INT,
    total DECIMAL(10,2),
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id)
);

DROP: Elimina por completo un objeto de la base de datos (tabla, base, etc.), estructura y datos incluidos.
TRUNCATE: Vacía todos los datos de una tabla, pero mantiene su estructura.
DELETE: Borra filas específicas según una condición en WHERE. 
DROP TABLE usuarios;
TRUNCATE TABLE pedidos;
DELETE FROM usuarios WHERE id = 5;

4: Diccionario de datos

El diccionario de datos es la documentación que describe cada tabla y cada columna de la base de datos: nombre, tipo de dato, si acepta NULL, restricciones (PK, FK, UNIQUE), y una breve descripción de qué representa. Sirve como referencia para cualquiera que trabaje con la base sin tener que leer el código SQL.

6: Normalización

La normalización es el proceso de organizar las tablas de una base de datos para reducir la redundancia y evitar inconsistencias, dividiendo la información en tablas relacionadas.

Cada columna debe tener valores atómicos (no listas ni datos repetidos dentro de una misma celda), y cada fila debe ser única.

Cumple la 1FN, y además todos los atributos que no son clave dependen de la clave primaria completa (aplica sobre todo cuando la PK es compuesta).

Cumple la 2FN, y además ningún atributo no clave depende de otro atributo no clave (elimina dependencias transitivas).

7: DER (Diagrama Entidad-Relación)

  • Usar nombres claros y consistentes para tablas y columnas.
  • Definir siempre una PK por tabla.
  • Marcar bien las relaciones (1 a 1, 1 a muchos, muchos a muchos) y su cardinalidad.
  • Normalizar antes de diagramar, para evitar redundancias en el modelo.

Además del clásico diagrama entidad-relación, el modelo se puede representar como un diagrama de bloques: cada tabla es un rectángulo con la lista de sus columnas adentro, y líneas que conectan las FK con las PK de otras tablas. Es la forma que usan herramientas como MySQL Workbench o dbdiagram.io.
